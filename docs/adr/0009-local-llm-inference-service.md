# ADR-0009: `민원인` 연기와 채점을 시연 장비의 로컬 LLM으로 돌린다

- 상태: accepted
- 날짜: 2026-09-11
- 관련: [[ADR-0001]] 턴 구조 · [[ADR-0005]] 강도 · [[ADR-0006]] 음성 폐기 · [[ADR-0008]] 음성 서비스

## 맥락

`민원인` 대사 생성과 `태도 3축` 채점은 Claude API(`claude-opus-5`)로 계획되어 있었다.
이를 외부 LLM API 없이 시연 장비 한 대에서 끝내기로 한다.

시연 장비는 RTX 5060 Ti(전용 VRAM 8GB) · RAM 64GB · Intel Core Ultra 7이다. 이 결정에 걸리는 제약은 다음과 같다.

- VRAM 8GB를 `음성 서비스`의 STT(faster-whisper)와 LLM이 나눠 쓴다.
- 턴은 언제나 사용자가 닫고([[ADR-0001]]), 사용자는 "말하기 끝내기" 뒤 `민원인` 음성을 기다린다. 대사 생성 속도가 곧 턴 지연이다.
- 채점은 연기와 병렬로 호출하고, 응답은 구조화된 형식이어야 한다(PRD).

## 결정

### 모델

연기와 채점 모두 **Qwen3.6-35B-A3B**(Apache 2.0)를 쓴다. 공식 가중치에서 양자화한 GGUF만 쓴다.

선택 기준은 **시연 장비에서 턴 지연을 지키는 가장 큰 모델**이다. 총 35B 중 토큰당 약 3B만 활성화되는 MoE라,
전문가 가중치를 RAM에 두고 나머지를 GPU에 두면 VRAM 8GB에서도 대화 속도가 나온다.

- **양자화**: Q4_K_M(약 21GB)으로 개발을 시작한다. RAM상 상한은 Q8_0(약 35GB)이다.
  RAM에 둔 전문가 연산은 메모리 대역폭에 묶여 양자화가 높을수록 느려지므로, 파일럿에서 턴 지연 목표를 지키는 가장 높은 양자화로 확정한다.
- **비전 인코더(mmproj)는 로드하지 않는다.** 텍스트만 쓴다.

### 서빙: `추론 서비스`

llama.cpp의 `llama-server`로 띄운 OpenAI 호환 HTTP 서비스를 `추론 서비스`라 부른다.
`음성 서비스`와 마찬가지로 127.0.0.1에 바인딩하고 Spring만 호출한다. 프롬프트를 조립하지 않고 카드와 루브릭을 모른다.

- CUDA 빌드(Blackwell 지원판)를 쓴다. Vulkan 백엔드는 이 모델 아키텍처에서 추론 중 크래시가 보고된 적이 있어 쓰지 않는다.
- Ollama는 쓰지 않는다. 전문가 오프로딩과 KV 캐시 양자화를 제어할 수 없다.

실행 기준값:

```bat
llama-server -m Qwen3.6-35B-A3B-Q4_K_M.gguf ^
  -ngl 99 --n-cpu-moe 99 -fa on ^
  --cache-type-k q8_0 --cache-type-v q8_0 ^
  -c 16384 -np 2 --jinja ^
  --host 127.0.0.1 --port 8081
```

`--n-cpu-moe`는 99(전문가 전부 RAM)에서 시작해, 아래 배치표의 VRAM 계획값에 닿을 때까지 줄여 GPU에 더 올린다.

### 자원 배치

| 구성요소 | 위치 | 계획값(실측 전) |
|---|---|---|
| faster-whisper (STT) | GPU | 약 1.5GB |
| `추론 서비스` 어텐션·공유 레이어·KV 캐시 | GPU | 약 5GB |
| 시연 브라우저·OS 화면 | GPU | 약 1GB |
| `추론 서비스` 전문가 가중치 | RAM | 약 21~35GB (양자화에 따라) |
| MeloTTS (TTS) | CPU | — |

NVIDIA 제어판의 CUDA 시스템 메모리 폴백을 끈다("폴백 안 함 우선").
VRAM이 넘칠 때 조용히 수십 배 느려지는 대신 에러로 드러나게 하기 위해서다.

### 호출 규칙

| 항목 | 연기 | 채점 |
|---|---|---|
| 슬롯 | 0번 고정 | 1번 고정 |
| 추론 모드(thinking) | 끔 | 끔 |
| temperature | 0보다 크게, 세션마다 시드 기록 | 0, 고정 시드 |
| 응답 형식 | JSON 스키마(대사, 진정 여부) | JSON 스키마(3축 점수, 근거) |
| 캐시 예열 | 세션 시작 버튼을 누른 시점에 카드·강도 프롬프트 | 서버 기동 시 루브릭 |

- **슬롯 고정**: 같은 모델이지만 컨텍스트가 분리되어 "채점 모듈은 `민원인`이 무엇을 말할지 모르고, 연기 모듈은 점수를 모른다"는 경계가 유지된다. 두 용도의 프롬프트 캐시가 서로를 밀어내지도 않는다.
- **추론 모드 끔**: 켜면 대사 한 줄 전에 수백 토큰을 생성해 턴이 끊긴다. 이 모델은 `/no_think` 명령이 없으므로 요청 파라미터로 끈다.
- **채점 temperature 0 + 고정 시드**: 같은 발화에 같은 점수가 나와야 저장 발화 기반 테스트가 성립한다.
- **JSON 스키마 제약 디코딩**: 토큰 단계에서 형식이 강제된다. 점수 범위와 필수 값 검증은 애플리케이션이 계속한다.

채점 요청 예:

```json
{
  "messages": [ ... ],
  "id_slot": 1,
  "temperature": 0,
  "seed": 42,
  "chat_template_kwargs": { "enable_thinking": false },
  "response_format": {
    "type": "json_schema",
    "json_schema": { "name": "attitude_score", "schema": { ... } }
  }
}
```

**병렬 호출.** 연기와 채점은 PRD대로 병렬 호출하되, 한 대의 연산을 나눠 쓰므로 연기가 느려진다.
파일럿에서 연기 지연이 목표를 넘으면 채점 요청을 연기 응답 완료 직후(`민원인` 음성 합성·재생 구간)로 미룬다.
PRD가 점수 갱신이 반 박자 늦는 것을 허용하므로 규칙 안의 조정이다. 채점 근거 문장은 짧게 제한한다.

### 출력 검사

로컬 모델은 프롬프트 지시만으로 절대선을 지킨다고 믿을 수 없다. 사용자가 도발 발화로 모델을 흔들 수 있다.
따라서 `민원인` 대사는 `음성 서비스`로 넘기기 전에 두 가지를 검사한다.

1. [[ADR-0005]]의 절대선 문서에 있는 금칙 표현이 없을 것
2. 대사가 한국어일 것 — Qwen 계열은 한국어 출력 중 한자·중국어 문장이 섞이는 현상이 보고된다

통과하지 못한 대사는 합성하지도, 화면에 보여주지도 않고 해당 턴만 재시도한다.
재시도도 실패하면 `훈련 세션`을 "시스템 오류로 중단"으로 끝낸다.
검열 제거(abliterated·uncensored) 변형 가중치는 절대선 방어를 스스로 무너뜨리므로 쓰지 않는다.

### 동시 세션

`추론 서비스` 한 대가 한 세션의 연기와 채점만 감당한다.
진행 중인 `훈련 세션`이 있으면 다른 세션 시작 요청은 거절하고 대기 안내를 띄운다.

### 폴백

턴 지연을 끝내 맞추지 못하면 **Qwen3.5-9B(Q4_K_M)**로 내린다. VRAM에 통째로 들어가 가장 빠르다.
연기·채점 모듈은 OpenAI 호환 API로만 LLM을 부르므로 모델 파일과 실행 인자만 바꿔 전환한다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| Claude API 유지 | 품질·안전성이 높고 설정 부담이 없다. 로컬 결정과 배치되어 기각 |
| Qwen3.8-27B (dense) | 최신이지만 8GB에서 대부분이 RAM에서 돌아 턴 지연을 지킬 수 없다 |
| Qwen3.5-122B-A10B (MoE) | 4비트로도 약 70GB대라 RAM 64GB를 넘는다 |
| Gemma 4 26B-A4B (MoE) | 장비에서 돌아간다. 한국어 대사 자연스러움 비교용 A/B 후보로 둔다 |
| Qwen3.5-9B | 가장 빠르지만 "가능한 가장 큰 모델" 기준에 못 미친다. 폴백으로 둔다 |
| Ollama로 서빙 | 전문가 오프로딩·KV 캐시 양자화를 제어할 수 없어 기각 |

## 결과

**좋아지는 것**

- 외부 API 호출 비용이 없다. 저장 발화 묶음을 쓰는 채점·강도 테스트를 모델이나 양자화를 바꿀 때마다 전부 다시 돌릴 수 있다.
- 시연 중 네트워크가 필요 없다.
- 사용자 전사 텍스트가 장비 밖으로 나가지 않는다. [[ADR-0006]]과 같은 방향이다.
- 채점을 temperature 0과 고정 시드로 돌려 재현성을 확보한다.

**나빠지는 것**

- 동시 세션이 하나로 제한된다.
- VRAM을 LLM에 내주므로 TTS를 GPU 모델(Qwen3-TTS 등)로 바꾸는 선택지가 막힌다. MeloTTS를 CPU로 유지하며 [[ADR-0008]]은 그대로다.
- 절대선 방어를 프롬프트가 아니라 출력 검사가 떠안는다.
- 조율할 변수(양자화, `--n-cpu-moe`, 슬롯, 컨텍스트 길이)가 늘어 일정 앞쪽에 부담이 몰린다.
- 대사와 채점 품질이 프론티어 API보다 낮을 수 있다.

## 확인해야 할 가정

- **턴 지연 목표가 없다.** "말하기 끝내기"부터 `민원인` 음성이 시작되기까지의 목표 시간을 정하고, 양자화별로 실측한다.
- **한국어 `민원인` 연기 품질 미확인.** 존댓말·반말 전환, 매장 손님다운 구어체, `강도`별 수위 차이가 카드대로 나오는지 `공식 카드` 전부로 확인한다. 부족하면 Gemma 4 26B-A4B와 비교한다.
- **채점 일관성 미확인.** 축 독립성 테스트와 직무 조치 비채점 테스트를 통과하는지 먼저 본다. 실패하면 루브릭을 고치기 전에 모델 문제인지 루브릭 문제인지부터 가른다.
- **VRAM 계획값은 추정이다.** KV 캐시는 대화가 길어질수록 커지므로 `하드 턴 상한`을 채운 세션 기준으로 잰다. 슬롯당 컨텍스트(`-c 16384 -np 2` → 슬롯당 8192)가 그 세션을 담는지도 확인한다.
- **병렬 호출이 연기 지연에 주는 영향 미측정.**
- **`id_slot`·`chat_template_kwargs` 지원 여부는 받은 `llama-server` 버전에서 확인한다.**
