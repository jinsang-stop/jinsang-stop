# 음성 훈련을 턴 기반으로 구현하고, 민원인은 사용자의 말을 끊지 않는다

상태: accepted

사용자는 마이크를 열어 말한 뒤 "말하기 끝내기"를 눌러 자신의 턴을 닫는다. 그때서야 전사가 확정되고
민원인이 응답한다. 민원인이 사용자 발화 중간에 치고 들어오는 일은 없으며, 발화 턴의 경계는 언제나
사용자의 버튼 조작이 정한다. 파이프라인은 녹음 → STT → 민원인 응답 생성 → TTS의 순차 구조다.

실시간 스트리밍 음성으로 가면 "말을 끊고 들어오는 진상"이라는 가장 압박감 큰 상황을 재현할 수 있지만,
에코 제거·발화 종료 감지·부분 전사 청크 정렬 같은 문제가 한꺼번에 따라오고, 채점기가 끝나지 않은 문장을
다뤄야 해서 점수가 불안정해진다. 우리는 **끊기의 무력감을 재현하는 것을 포기하는 대신**, 발화 전문이 확정된
상태에서 채점하는 안정성과, 디버깅·비용 예측이 가능한 단순한 파이프라인을 얻는다.

이 결정은 채점기가 항상 완결된 발화 하나를 입력으로 받는다고 가정해도 된다는 뜻이다. 대화 로그 스키마도
"사용자 발화 1 : 민원인 응답 1"의 쌍으로 고정된다. 나중에 끊기를 도입하려면 스키마·채점기·프론트 오디오 계층을
모두 다시 써야 하므로, 그때는 이 문서를 superseded로 두고 새 ADR을 쓴다.
