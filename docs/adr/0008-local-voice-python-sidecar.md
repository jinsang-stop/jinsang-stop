# 음성 인식과 합성은 로컬 모델로 처리하고, 파이썬 음성 서비스를 별도로 둔다

상태: accepted

STT는 faster-whisper, TTS는 MeloTTS(`language='KR'`)를 로컬에서 돌린다. 둘 다 파이썬 라이브러리여서
Spring에서 직접 호출할 수 없으므로, 음성 처리만 담당하는 파이썬 HTTP 서비스를 별도 프로세스로 띄우고
Spring이 그 앞에 선다. 브라우저는 Spring하고만 통신하고 파이썬 서비스는 외부에 노출하지 않는다.

상용 음성 API를 쓰면 서비스가 둘로 끝나고 한국어 품질도 검증된 것을 쓸 수 있지만, 사용량만큼 비용이 나가고
학기 중 키 관리와 결제 수단이 필요하다. 우리는 **서비스 하나를 더 운영하는 단순함과, 검증된 상용 음성 품질을
포기하는 대신**, 사용량과 무관하게 비용이 0이고 오디오가 외부로 나가지 않는다는 점을 얻는다. 오디오가 우리
프로세스 밖으로 나가지 않으므로 [[ADR-0006]]의 음성 비보관 약속도 더 지키기 쉬워진다.

이 결정은 배포 단위가 셋(React · Spring · 파이썬 음성 서비스)이라는 뜻이고, 개발 환경 구축 문서와 실행 방법이
프로젝트 산출물에 포함되어야 한다는 뜻이다. 또한 음성 처리 지연이 우리 하드웨어 성능에 직접 묶이므로,
시연 장비의 사양이 곧 사용자 경험이 된다. MeloTTS가 노출하는 조절 파라미터는 확인된 범위에서 `speed`와
`speaker_id`뿐이므로 민원인의 분노 어조는 음성이 아니라 대사 자체로 표현해야 한다 — 이는 [[ADR-0006]]이
이미 만든 제약(채점은 전사 텍스트만 본다)과 같은 방향이다.
