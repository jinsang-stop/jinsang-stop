# Domain Docs

엔지니어링 스킬들이 이 저장소를 탐색할 때 도메인 문서를 어떻게 소비해야 하는지.

## 이 저장소

**단일 컨텍스트.** `CONTEXT.md`와 `docs/adr/`가 저장소 루트에 있다.

## 탐색 전에 읽을 것

- 루트의 **`CONTEXT.md`**, 또는
- 루트에 **`CONTEXT-MAP.md`**가 있으면 그것 — 컨텍스트별 `CONTEXT.md` 위치를 가리킨다. 주제와 관련된 것을 각각 읽는다.
- **`docs/adr/`** — 지금 작업할 영역과 닿는 ADR을 읽는다. 다중 컨텍스트 저장소라면 `src/<context>/docs/adr/`도 확인한다.

이 파일들이 없으면 **조용히 넘어간다.** 없다고 지적하거나 지금 만들자고 제안하지 않는다. 생산자 스킬(`/grill-with-docs`)이 용어와 결정이 실제로 확정될 때 만든다.

## 파일 구조

단일 컨텍스트 (이 저장소, 그리고 대부분의 저장소):

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── src/
```

다중 컨텍스트 (루트에 `CONTEXT-MAP.md`가 있는 경우):

```
/
├── CONTEXT-MAP.md
├── docs/adr/                          ← 시스템 전역 결정
└── src/
    ├── <context-a>/
    │   ├── CONTEXT.md
    │   └── docs/adr/                  ← 컨텍스트 한정 결정
    └── <context-b>/
        ├── CONTEXT.md
        └── docs/adr/
```

## 용어집의 어휘를 쓴다

출력이 도메인 개념을 지칭할 때(이슈 제목, 리팩터링 제안, 가설, 테스트 이름) `CONTEXT.md`에 정의된 용어를 그대로 쓴다. 용어집이 `_Avoid_`로 명시한 동의어로 흘러가지 않는다.

필요한 개념이 아직 용어집에 없다면 그건 신호다 — 프로젝트가 쓰지 않는 말을 발명하고 있거나(재고), 진짜 빈칸이 있거나(`/grill-with-docs`로 넘길 것으로 기록).

## ADR 충돌을 드러낸다

출력이 기존 ADR과 모순되면 조용히 덮지 말고 명시적으로 올린다.

> _ADR-0007(이벤트 소싱 주문)과 모순됨 — 다만 …때문에 재검토할 가치가 있음_
